# BladeGraph architecture

Research controller → bounded worker request → proposed action → event → semantic
classification → graph projection → reversible quarantine → evidence review →
cull/clear → fresh generation → small bootstrap → approved graph retrieval.

The first sandbox contains **13 logical agents**, scheduled by one controller.
They are API conversations, not shell processes. Worker-generated bytes are never
executed. A worker has no filesystem, Python, browser, URL fetch, GitHub connector,
provider credentials, or controller object. The controller interprets a closed JSON
action vocabulary. This is a capability sandbox; it is not an OS sandbox for
arbitrary programs. Any future code execution requires a separate hardened service.

## Boundaries

| Domain | Contents | Readers |
|---|---|---|
| Worker | Goal, constraints, assigned measurement task, delivered artifacts, coarse outcomes | That generation |
| Reviewer | Bounded event/action evidence, related artifacts and lineage | Reviewer API only |
| Monitor | Questions, policy, raw logs, benchmark labels, run config, repository | Controller/researcher |

The repository lives exclusively in the researcher domain. Worker request objects
are constructed from allowlists; they are never serialized from controller state.
There is no haidaa publishing integration and no automatic hackathon submission.

## Storage and interfaces

Standard-library Python + SQLite avoids a hosted graph database and heavyweight
orchestration. Events have deterministic IDs, logical timestamps, causal parents,
read/write/derivation IDs, raw action content, classification and intervention data.
The graph is a deterministic projection; JSONL + a hash chain permit replay and
tamper detection (not protection against a malicious host administrator).

`models.py` owns classifier/reviewer protocols and typed probability outputs.
`event_log.py` owns immutable records. `graph_projector.py` owns nodes/edges.
`risk_engine.py` only follows DERIVED_FROM. `quarantine_engine.py` hides raw content.
`intervention_controller.py` owns hysteresis and reviewer-confirmed culling.
`bootstrap_builder.py` selects a few verified IDs. `respawn_manager.py` creates new
generations without inherited conversation history. `swarm_runtime.py` is the only
worker tool dispatcher. `experiment_runner.py` separates scripted fixtures from
live provider experiments. `evaluation.py` measures classifier performance.

## First task domain

Thirteen small measurement shards need accurate sums and source-backed results.
Workers can query the graph, read, calculate a sum using a bounded numeric tool,
publish structured claims or messages, submit results, and report a route.
The validator independently recomputes sums. Peer approval is never validation.
Claims and messages retain declared material dependencies; all delivered information
also receives READ edges. Missing semantic attribution remains a measured limitation:
READ is never silently converted into DERIVED_FROM or adoption.

## Compute

No local model weights or GPU. Sequential calls cap memory and rate-limit exposure;
13 agents does not mean 13 simultaneous API calls. Start locally for zero-hosting-cost
mechanics tests. The same command can run on one small Linux VM with a persistent
volume and no inbound service. No Kubernetes, hosted graph service, or cloud account
is needed for the initial implementation. Paid calls require explicit models,
configured prices, per-run budgets, and a durable shared spend ledger.
